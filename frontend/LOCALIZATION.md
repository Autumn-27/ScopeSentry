# 한국어 UI 구현 및 검증 기록

## 구현 범위

- 기존 vue-i18n 동적 로드·Pinia locale store·ConfigGlobal 구조에 `ko-KR` 추가함.
- Element Plus `ko`와 한국어 상대 시간 연결. 영어 메시지를 미리 로드해 fallback 적용함.
- 기본 언어 `zh-CN` 유지. 기존 sessionStorage 선택값 이관 및 localStorage 영구 저장 적용함.
- 중국어·영어 선택, 기존 번역 키와 보간 변수 유지함.
- 화면 문구와 프런트엔드 자체 오류 안내만 번역. API·인증·Go·스캔 코드 수정 없음.

원본 영어 780개, 중국어 전용 7개, 분리한 UI 문구 69개와 언어 변경 경고 1개를
합쳐 세 언어 각각 **857개 키**로 맞춤. 영어에는 중국어 전용 키 7개, 중국어에는
영어 전용 키 2개 보완함. 기존 오타 키도 호환성을 위해 유지함.
상대 시간 메시지 11개는 `useTimeAgo.ts`에서 별도 처리.

## 언어 전환 동작

- 브라우저 전체 reload 없이 HTML 언어·화면 제목 갱신.
- Element Plus provider는 유지하고 콘텐츠 slot만 언어별 key로 재생성.
- 초기화 시 번역되는 테이블·폼 스키마와 캐시 화면의 이전 언어 잔류 방지.
- 확인창 취소·닫기 시 현재 언어와 입력 유지. 승인 시 입력·화면 상태 초기화 가능.
- 전환 중 추가 선택 무시. 언어 로드 실패 시 메뉴 잠금 해제.
- router와 언어 이벤트에 일회성 `setPageTitle` 적용. 컴포넌트 수명주기 밖의
  watcher 생성 방지. 기존 `useTitle` 인터페이스 유지함.

승인한 전환은 라우터·레이아웃·캐시·폼을 다시 생성하므로 mount hook의 조회가
재실행될 수 있음. 이미 전송한 요청은 취소·재전송·롤백하지 않음.
전환 잠금은 언어 로드의 중복 실행만 방지하며 업무 요청을 직렬화하지 않음.
확인창 방식의 수용 여부와 상태 보존 개선 필요성은 병합 전 유지보수자 검토 사항.

## 검증 명령

`frontend`에서 실행:

```sh
npm ci --ignore-scripts
node scripts/check-locales.mjs
node scripts/check-locale-stability.cjs
npx vue-tsc --noEmit --skipLibCheck
npx vite build --mode pro
npx vite --mode base --host 127.0.0.1 --port 5173
```

| 항목 | 결과 |
| --- | --- |
| 번역 키·빈 값·보간 변수 검사 | 통과: 세 언어 857개, 한국어 누락 0 |
| 대표 보간·영어 fallback 검사 | 통과 |
| 독립 컴포넌트 회귀 검사 | 통과 |
| Production build | 통과. 기존 Vite CJS·Browserslist 경고 유지 |
| 전체 TypeScript 검사 | 실패: 기존 진단 151개 |
| 원본 HEAD 대비 TypeScript 진단 | 추가 0, 삭제 0 |

원본 기준은 `d770b7a137ec2de15816fea4bd561f49cf486db2`. 같은 의존성으로 원본과
변경본을 검사하고 경로·행·열 위치를 정규화해 진단 내용 비교함.
미사용 import, 자산/API 응답 타입, 누락 props 등 기존 문제는 수정하지 않았음.
전체 TypeScript 검사 통과를 의미하지 않음.

`check-locales.mjs`는 영어·중국어 키 합집합, 한국어 빈 값, 보간 이름,
대표 보간 결과와 영어 fallback 검사. fallback은 검사 전용 사본에서 키 하나를 제거해 확인함.

`check-locale-stability.cjs`는 실제 dropdown·ConfigGlobal 소스를 기존 Vue·TypeScript
도구로 컴파일해 검사. 취소·닫기, 동일 언어 선택, 중복 전환, 실패 복구,
provider 유지, 콘텐츠 재생성, 입력 보존·초기화 및 제목 101회 갱신 시 새 watcher 0개 확인.
비동기 수명주기 검사는 합성 Promise이며 실제 API 통합 검사가 아님.

## GUI 검증 기록

- localhost 로그인 화면 1280×720, 로그인·확인창 411×827 레이아웃 확인.
- 중국어·영어·한국어 전환, 제목 갱신, 새로고침·새 탭의 언어 유지 확인.
- 합성 사용자 이름 입력 후 전환 취소 시 입력 유지, 승인 시 초기화 확인.
- 원본 HEAD의 중국어 로그인·2개 언어 메뉴와 변경본의 한국어 로그인·3개 언어
  메뉴를 같은 브라우저의 1280×720 화면에서 직접 촬영함.
- 로그인 입력란이 빈 상태로 비교 캡처. 인증정보 입력·로그인 제출·운영 연결 없음.
- 이번 문체 검토에서는 GUI를 추가로 실행하지 않았음. 변경 문구의 실제 화면 배치는 재검증하지 않았음.

비교 캡처와 상세 로그는 별도 PR 검토 자료로 보관. 인증 후 화면의 원문 스크린샷을
이번 변경의 검증 증거로 재사용하지 않았음.

## 미검증·알려진 제한

- 실제 로그인·로그아웃과 재로그인 후 언어 유지.
- 인증 후 대시보드, 자산 조회·검색, 스캔 생성, 프로젝트, 플러그인,
  POC·기술 식별, 민감정보, 사전, 시스템 설정의 GUI·API 동작.
- 실제 진행 중 요청의 언어 전환 영향, 스캔 실행, MCP 연결, 서버·이미지 빌드와 배포.
- 나머지 인증 화면·반응형 레이아웃 및 변경 문구의 줄바꿈·잘림.
- 백엔드 `message`, 플러그인 이름·소개, 원본 오류·로그의 혼합 언어.
- 비활성 관리자 템플릿 데모와 legacy copy/bak 컴포넌트의 포괄적 번역.

서버 응답 타입에 안정적인 UI 번역 키가 없어 메시지를 그대로 표시함.
완전한 응답 번역에는 별도 백엔드 카탈로그나 메시지 코드 계약이 필요하며,
이번 변경에서 Go 코드나 API 언어 헤더는 수정하지 않았음.

설치된 Element Plus 2.6.3에는 중국어 `el.messagebox.close` 값이 없어 닫기 버튼의
접근성 이름에 키가 표시될 수 있음. 한국어·영어의 갱신은 확인함. 의존성 업데이트는 하지 않았음.

## 사용자 문서와 원문 차이

- 영어·중국어 README의 서버 `python - FastApi` 표기는 현재 Go/Gin 소스와 다름.
  기존 본문은 유지하고 한국어 README는 현재 소스 기준으로 작성함.
- 중국어 README에는 ICP·앱·미니 프로그램 수집, PDF 민감정보 스캔, 데이터
  내보내기 설명이 추가로 존재. 약한 비밀번호 대입과 관계도는 원문 예정 항목.
  기능 소개를 실행 검증 결과로 취급하지 않음.
- MCP 설정은 공식 `SKILL.md`와 `internal/mcp` 구현을 근거로 정리함. 실제 연결 미검증.
- 기존 v1.9.4·`latest` 이미지에 이 PR의 한국어 UI가 포함됐다고 확인하지 않았음.
- 영어 README의 Discord 초대 링크가 서로 달라 중국어와 공유하는 링크를 사용함.
  초대 유효성 미검증.

## 빌드·배포 구분

통합 저장소의 release workflow는 `frontend/dist-pro`를 `cmd/main/static`에
병합한 뒤 Go 서버 바이너리에 embed함. 실행 중 컨테이너의 static 디렉터리에
프런트엔드 파일을 복사하는 것만으로 기존 바이너리의 UI는 바뀌지 않음.

배포 시 같은 소스 리비전의 별도 staging에서 기존 release 절차로 서버·이미지
빌드 및 통합 검증 필요. `draco`, `lib`, `plugins` 등 부가 자산과 운영 설정·볼륨·
노드·인증정보 보존. 실제 Compose 서비스·이미지 이름 확인 후 적용하며 이전 이미지로 복구 가능해야 함.
MongoDB 초기화나 `docker compose down -v`는 수행하지 않음.

이번 작업에서 Kali·ARTEX·Docker·운영 데이터를 변경하지 않았음.
프런트엔드 build 통과와 서버·이미지 빌드 및 운영 배포 검증은 별개.

  문체·용어 변경은 별도 commit으로 분리. Push·PR 생성은 수행하지 않았음.
- 독립 ScopeSentry-UI에 제출할 경우 리비전과 frontend 상대 경로를 별도 대조할 필요 있음.
- 기존 라이선스·저작권 고지 유지. 루트 README는 AGPL-3.0 및 추가 상업 이용 조건,
  frontend/LICENSE는 MIT·Archer 저작권, Swagger 메타데이터는 Apache 2.0 명시.
  고지의 적용 관계를 재해석하거나 새로운 상업 이용 권한을 부여하지 않음.

Draft PR 검토 준비는 가능. 병합·운영 적용 전 인증 후 통합 회귀 검증,
언어 전환의 상태 초기화 방식 및 기존 TypeScript 실패에 대한 유지보수자 판단 필요.
